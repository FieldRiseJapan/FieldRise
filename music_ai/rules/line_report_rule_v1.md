# LINE定時報告 運用ルール Ver.1

## 1. 基本コンセプト
- **「1分以内で読める」** ことを最優先とする。
- LINEは概要とポジティブなエネルギーを伝える場、GitHubは詳細な事実と技術データを蓄積する場として役割を分担する。

## 2. 言葉遣いとトーン
- **表現:** 「日報」ではなく「定時報告」に統一する。
- **雰囲気:** 明るく、親しみやすく、可愛らしいトーン。
- **装飾:** 絵文字（🌸, ✨, 😊 等）や顔文字（(*´︶`*), ٩(ˊᗜˋ*)و 等）を適度に使用する（1〜3個程度）。

## 3. 報告フォーマット（標準）
```text
🌸 おはようございます、社長！
✨ 本日の定時報告です♪

【今日（昨日）の成果】
・〇〇
・〇〇
・〇〇

【本日のおすすめ】
〇〇を進めることをおすすめします。

📁 詳細分析はGitHubへ保存済みです。

🌸 今日も「最小のCreditで、最大の価値を。」を大切に、一緒にFieldRiseを育てていきましょう！
```

## 4. GitHubとの役割分担
| 項目 | LINE (概要) | GitHub (詳細) |
| :--- | :--- | :--- |
| **完了タスク** | 箇条書きで簡潔に | コミットID、具体的な変更内容 |
| **分析結果** | 「分析完了」の報告のみ | 数値、Key、コード、構成図 |
| **技術資料** | 「保存済み」の案内のみ | 全文、テンプレート、仕様書 |
| **メッセージ** | 前向きな一言、おすすめ作業 | 次のステップの技術的詳細 |
