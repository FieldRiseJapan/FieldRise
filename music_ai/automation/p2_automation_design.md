# P2｜音源解析・台帳更新の自動化設計

**目的:** GitHub正本を壊さず、生成後の分析・差分・品質確認を速くする。SUNO生成の自動実行、外部アカウント操作、非公式API呼び出しは対象外とする。

## 実装済みの決定論的ツール

| ツール | 入力 | 出力 | 自動化してよい範囲 |
|---|---|---|---|
| `probe_intro.py` | 権利確認済みのローカル音源 | IntroのRMS、Peak、閾値到達時刻JSON | 波形測定のみ |
| `compare_metrics.py` | 正規化済みのA/B Metrics JSON | Metric ID単位の差分JSON | 数値差分のみ |
| `quality_gate.py` | 共通実験台帳 | Promotion阻止理由JSON | 昇格のブロックのみ。自動昇格はしない |

## 将来の安全な処理順

生成後に音源が提供された場合、音源ハッシュ・権利状態・対象IDを先に記録し、Intro Probeを実行します。次に候補用Metrics JSONを生成し、A/B Differenceを出します。その後に品質ゲートを実行し、結果を`latest_report.md`の下書きへ反映します。台帳の更新、Knowledge昇格、Prompt採用、SNS投稿は必ず人が承認します。

| 自動化候補 | 実装状態 | 実行の許可条件 | 人の承認点 |
|---|---|---|---|
| 分析入力の構造検証 | 設計済み | JSON Schemaと必須Evidenceが揃う | 必要なし |
| Intro／A-B差分解析 | 実装済み | 権利確認済み音源をローカルで指定する | 結果の解釈 |
| 台帳更新の下書き | 設計済み | 音源ID・Metrics・Prompt・設定が揃う | 正本へ反映する前 |
| 品質ゲート | 実装済み | 台帳に候補がある | Knowledge昇格の最終決定 |
| GitHub Actions実行 | 保留 | 社長承認後に、対象ブランチと権限を設計する | ワークフロー追加前 |
| SUNO生成実行 | 対象外 | 公式API・利用条件を確認し、別の明示指示を受ける | 常に人の最終操作 |

> **Blocker:** GitHub Actionsの追加はリポジトリ運用へ影響するため、本P2では設計までとし、実行ワークフローは追加しない。
