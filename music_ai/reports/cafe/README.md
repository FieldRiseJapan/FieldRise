# Cafe正式報告の運用ルール

このフォルダは、桃花（COO）から社長・彩花（CTO）へ提出する**正式な調査報告および作業完了報告**の保存先です。Cafeシリーズの分析そのものと、意思決定のための報告を分離し、毎回同じ入口から現在の判断材料を確認できるようにします。

| 区分 | 正式保存先 | 役割 |
|---|---|---|
| **分析データ** | `music_ai/analysis/cafe/` | 音響解析、比較JSON、波形・周波数の実測、Fact/Hypothesisの詳細根拠 |
| **最新報告** | `music_ai/reports/cafe/latest_report.md` | 社長・彩花が最初に読む固定入口。今回の結論、判断依頼、関連資料へのリンクを置く |
| **過去報告** | `music_ai/reports/cafe/archive/` | 提出済みの詳細調査、完了報告、意思決定の履歴を日付付きで保管する |

## 完了時の必須手順

作業が完了した時、桃花はまず分析データを役割に応じた正式フォルダへ保存します。その後、社長・彩花向けの結論、FactとHypothesis、保存先、コミットID、Push結果、次の判断事項を `latest_report.md` に反映します。直前の正式報告または今回の詳細報告は、日付・対象・版が分かる名称で `archive/` に保存します。

| 必須項目 | `latest_report.md`での記載内容 |
|---|---|
| 目的と結論 | 今回の作業目的、社長・CTOが最初に知るべき結論 |
| Fact / Hypothesis | 確認済みの事実と、未検証の提案を明確に分離する |
| 根拠資料 | 分析データ、詳細報告、基準仕様への相対リンク |
| 保存結果 | GitHub保存先、コミットID、Push結果 |
| 次の判断 | 次回の検証・設計・実装で、社長またはCTOが決める事項 |

> **運用原則:** `analysis` は分析そのもの、`reports` は桃花からの正式報告です。報告書を分析フォルダへ置かず、分析データだけを報告フォルダへ複製しません。最新の意思決定入口は常に `latest_report.md` とします。

## 彩花CTO向けの固定確認手順

彩花CTOは、まず `music_ai/reports/cafe/latest_report.md` だけを確認します。桃花は、詳細資料を`archive/`、`analysis/`、`reference/`、`experiments/`のいずれに保存しても、必ず`latest_report.md`から相対リンクで辿れるようにします。詳細資料だけを作成しても、`latest_report.md`が更新されなければ正式報告は未完了です。

| 完了報告の必須6項目 | 記載要件 |
|---|---|
| ① 完了状況 | 実行済み範囲と、設計のみか実装済みかを明確にする |
| ② 作成・更新ファイル | パスと、詳細資料へのリンクを示す |
| ③ コミットID | 最新の対象コミットを完全なSHAで記載する |
| ④ Push先 | 反映したリモート・ブランチを記載する |
| ⑤ 未完了・ブロッカー | ない場合も「なし」と明記する。推測で解消扱いにしない |
| ⑥ 彩花CTOが次に確認するファイル | 次の判断に必要な1〜2ファイルをリンクする |

> **完全な往復ルート:** 彩花CTOは `inbox/cto_to_coo/latest_instruction.md` で指示し、桃花COOは `reports/cafe/latest_report.md` で返答します。Issue、会話、詳細資料は補助情報であり、この2つの固定入口を置き換えません。

## 常時更新の絶対ルール

`latest_report.md` は完了報告だけのファイルではありません。桃花は、作業開始、途中進捗、停止地点、未完了、ブロッカー、完了のすべてを本ファイルへ記録します。

> **禁止:** 「未完了だから `latest_report.md` を更新しない」という判断は禁止です。未完了であること自体が、彩花CTOが確認すべき正式な報告事項です。

| 状態 | 必須記載項目 |
|---|---|
| 開始 | 指示ID、目的、範囲、開始日時 |
| 途中 | 到達した段階、作成・更新ファイル、Fact / Hypothesis、次の作業 |
| 停止・ブロッカー | 停止地点、原因、不足情報・承認、再開条件 |
| 完了 | 完了範囲、未完了、完全Commit SHA、Push先、次の確認ファイル |
