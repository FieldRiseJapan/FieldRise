# TikTok写真投稿準備 Phase 1

既存MP4画面・OAuth・Supabaseとは独立した、外部通信しない写真準備画面。

## PC操作
専用ブランチをcheckoutし、リポジトリ直下で `python -m http.server 8000 --bind 127.0.0.1` を実行。
PC Chrome/Edgeで http://localhost:8000/automation/sns_auto_posting/tiktok/photo/ を開く。
画像投入→比率と切り抜き位置→楽曲選択→投稿文生成と編集→画像保存とコピー→TikTok Studioで本人がアップロード・音源照合・公開。
公開後のURL・日時・数値は手入力。保存とJSON/CSV出力を使う。

## 境界
最大35枚を逐次加工。1画像最大20 MiB・24百万画素・各辺10000。JPG/PNG/WebPをMIMEとシグネチャで検証。先頭256 KiBから画像寸法を確認し、画素上限をデコード前と後に検査する。ヘッダーで寸法を確認できない画像は安全側で拒否する。
写真比率は社長指定の3:4/4:3/16:9。出力900x1200/1200x900/1600x900は本ツール設定でありTikTok必須規格とは扱わない。
タイトル90文字、説明1500文字・タグ300文字は保守的なツール上限。最終制限・公開設定はStudioの表示に従う。
TikTok公式写真API資料（参照2026-10-10）: https://developers.tiktok.com/doc/content-posting-api-reference-photo-post
APIは一切使用しない。PC操作確認は社長報告を基準とする。

テンプレート生成のみ。画像認識・トレンド・自動投稿・自動収益取得なし。cafe 0:59はStudio検索選択確認済み、SoundOn識別一致・印税は未検証。
localStorageは同一ブラウザ・同一Originのみ。他の同一Originページからもアクセス可能で、秘密値は保存しない。画像データは保存しない。Phase 2ではJSON再取込・記録編集・確認付き削除を実装。取込は追加専用、重複IDは全体を拒否して既存データを保護する。
切り抜きは中心＋左右上下位置。透過画像は白背景JPEG。小画像は拡大される。EXIF等の元画像メタデータはJPEG書き出しで維持しない。
Clipboardはlocalhost等の安全なコンテキストで利用可能。拒否時は手動コピー。TikTokの操作は本人のみ。

## Phase 2 音源・記録管理
楽曲編集欄へ読み込んで、ISRC・SoundOn ID・TikTok ID・URL・秒数・一致状態・確認者・日時・方法・根拠を登録する。確認済みは識別情報と公式URL・根拠が揃った場合のみ。ID体系は別欄で管理し、入力値の実在を自動証明しない。初期cafeは未確認。
投稿前チェックで警告確認。不一致は準備完了不可。未確認の継続は社長判断理由を必須とする。Studioの外部操作を禁止する機能ではない。
記録は音源情報のスナップショットを保持し、楽曲更新で過去の確認履歴を書き換えない。記録編集は数値・文章・URL・日時を更新し、過去音源根拠は保持。訂正音源は新しい記録を作る。
JSON schemaVersion=3、旧v1/v2とversion省略形式を移行。5 MiB・楽曲1000件・記録10000件制限。再取込は形式確認→件数確認→追加。重複ID時は上書きせず停止。既存記録と同IDのバックアップを再取込する場合は編集で更新し、全置換は実装しない。
収益未取得はnull/未確認。確認済みの数値は集計値で、投稿別因果や確定印税の証明ではない。集計待ちを別管理する。
ブラウザ保存失敗の場合、現在メモリのJSONを必ず出力。JSONは入力の既知項目のみ受け入れ、一般的な秘密値形式を拒否するが、機密情報を入力しないこと。

## Phase 3-A 複数写真と投稿セット
複数選択/ドロップ→共通比率→個別選択で左右上下切り抜き→↑↓で順序→全写真をZIP保存。ZIPは無圧縮・CRC32、外部依存なし。連番は表示順で001〜035、重複元ファイル名でも出力は重複しない。ブラウザの端末保存完了は本人が確認する。
上限35枚/合計元画像100 MiB/1枚20 MiB/24百万画素/各辺10000/処理並列数1/出力50 MiB。候補70件までを個別検査。ヘッダー寸法不明は拒否。一部失敗は成功分ZIP、失敗分は選択して個別再保存。ZIP失敗も個別保存可。元画像を保存/変更しない。透過は白背景JPEG品質0.92。
投稿セットは写真順序・元ファイル名/容量/更新日時・比率・切り抜き位置・音源スナップショット・文章・チェック・社長判断を保存。サムネイルと元画像はメモリのみ、localStorage/JSONへ含めない。再表示後に元ファイルを再選択。名前/容量/更新日時一致は照合補助であり画像の暗号学的同一性を保証しない。再表示後は未準備、Studio最終確認を再実施する。
前回文章/共通比率の呼出しは音源確認を流用しない。セット保存・更新・確認付き削除、JSONバックアップと追加再取込（重複拒否）。投稿記録にセットID/写真枚数を保存、CSVにも出力。
操作数比較（設計値）：N枚を個別に選択/比率指定/保存なら3N操作、一括方式では複数選択/共通比率適用/ZIP保存の3操作。切り抜き調整・並び替え・OSダイアログ・音源チェックは両方式の追加操作で比較から除外。実測時間/実機性能を示す値ではない。

## Phase 3-C：投稿文・予定管理
「新しい投稿セット」→写真一括投入→比率・順序→楽曲→6カテゴリ/長さから3候補生成→候補選択・編集/コピー→音源確認→ZIP保存→Studio本人操作→セット保存。一覧で検索・状態絞込み・日時順表示・複製・編集ができます。
予定/公開日時は日本時間で入力しUTCで保存。予定は管理情報のみ、予約・自動投稿なし。保存後「状態・予定・公開記録を更新」で変更。準備完了/投稿予定はセットを開き元画像と音源を再確認。未確認理由は下書きに保持、不一致は完了不可。投稿済みは本人申告URL/日時必須、公式音源一致とは別。複製は最終確認・予定・公開記録・判断理由をリセット。マスター更新は過去スナップショットを変更しません。
JSON v4はv1/v2/v3を読込、重複IDは上書きせず拒否。従来の記録CSVとセット一覧CSVを別々に保存。既存収益項目は保持するが収益計算・予測・自動取得は追加しません。画像本体は永続保存しません。ローカル生成はテンプレートによる候補で、AI解析・トレンド検索ではありません。PC実ブラウザ未検証。

## 完成統合版（開発版）
作業中セットの保存/更新を1つのボタンに統合。カテゴリ別文章と本人入力の楽曲雰囲気、同一文面履歴警告、タグ単独コピー、Studio移行案内、JST予定日範囲検索、文章履歴/再利用を追加。履歴の再生数は手入力の既存実測値のみ。未取得は0にしません。セット/記録の同一投稿は別行です。
JSON v5はv1～v4読込。追加フィールドは内容/目的/雰囲気、ビジネス音源利用可否と根拠。識別IDの推測、AI画像認識、収益計算は行いません。利用不可は完了拒否、未確認はStudioで本人の最終照合を要求。
端末保存失敗時はJSON退避と保存再試行。保存データが破損している場合は上書きを禁止し、元データを退避した後、画面の明示確認で保存再開できます。未保存編集で別セットを開く/新規開始する場合は確認。ページ離脱時はブラウザに警告を要求しますが環境により表示されないことがあります。
起動：リポジトリのルートで `python -m http.server 8000 --bind 127.0.0.1`、PCブラウザで `http://127.0.0.1:8000/automation/sns_auto_posting/tiktok/photo/`。固定の同じブラウザ/URLを使用してください。Productionには反映していません。
