# Project-001｜Fender Studio ローカル制作・ファイル連携ワークフロー

**目的:** 社長がFender Studioで001・002の編集を行い、Manus AI（COO）が設定設計、測定、改善案、GitHub記録を担う。Fender Studioの画面を遠隔操作しなくても、再現精度を段階的に上げるための標準手順である。

## 1. 役割分担

| 担当 | 役割 | 完了条件 |
|---|---|---|
| 社長 | Fender Studioでトラックを配置、編集、書き出し、主観的な聴取確認を行う。 | 指定の書き出しファイルと作業メモを共有する。 |
| Manus AI（COO） | 001・002の数値目標、編集順、候補評価、再測定、次の一変数変更を提示する。 | `latest_report.md`と詳細分析をGitHubへ更新する。 |
| 彩花CTO | 設計・再現方針をレビューし、次の検証条件を確定する。 | 指示書またはレビューをGitHubへ記録する。 |

> **原則:** 一回の検証で変更するのは一変数だけである。音量、帯域、Stereo幅、導入時刻、Piano導入、Drums導入を同時に変えない。

## 2. 初回セットアップ

社長のWindowsまたはMacに、Fender Studioと同期用フォルダを用意する。Fender Studioの操作画面・アカウント情報・パスワードは共有しない。同期フォルダに置くのは、利用権限を確認済みの音源、書き出し音源、編集メモだけとする。

```text
FieldRise_MusicAI/
├── Project001_FenderStudio/
│   ├── 00_reference/      # 001/002正本。読み取り専用で保管
│   ├── 01_source/         # Suno等の候補曲。元ファイルを変更しない
│   ├── 02_fender_project/ # Fender Studio上の編集プロジェクト
│   ├── 03_exports/        # WAVとMP3の書き出し先
│   ├── 04_stems/          # 可能な場合のみBass/Piano/Drums等のステム
│   └── 05_notes/          # 編集メモ、manifest、聴取チェック表
```

### 推奨する引き渡しファイル

| 優先度 | ファイル | 用途 |
|---|---|---|
| 必須 | `001_or_002_mix_vNN.wav`、48 kHz、24-bit、Stereo | 客観測定と次の改善提案。 |
| 必須 | `001_or_002_manifest_vNN.json` | 変更変数、開始時刻、書き出し日時、素材IDを追跡する。 |
| 推奨 | `001_or_002_mix_vNN.mp3` | 日常端末での聴取確認。判定の正本には使わない。 |
| 可能なら | `001_or_002_bass_vNN.wav`などのステム | 楽器混入、ノイズ、音色・アタックの確認。 |
| 任意 | `001_or_002_listening_notes_vNN.md` | クリック音、違和感、Loop感などの主観記録。 |

## 3. 001用編集シート

001は「導入の低域集中、狭い空間、過度に前へ出ないBass」を最初に固定する。既存の測定では、導入0〜2秒の目安として、RMSは-22.64 dBFS、Low（20〜180 Hz）比率は98.04%、Low-mid（180〜2,000 Hz）比率は1.80%、Side/Mid比は-32.40 dBである。[1]

| 編集順 | Fender Studioでの操作 | 確認目的 |
|---|---|---|
| 1 | 001参照音源と候補音源を別トラックへ読み込み、参照音源はミュート・ロックする。 | 正本を変更しない。 |
| 2 | 0:00〜2.00秒の候補トラックを、Bass以外が鳴らない導入として編集する。 | Bass単独性を作る。 |
| 3 | Bassを中央定位にし、左右に異なる空間処理・パン・広がりを加えない。 | Stereo幅を小さくする。 |
| 4 | 2.00秒以降にPianoを自然に導入し、Drumsは後段で最小限にする。 | 導入の一変数検証を守る。 |
| 5 | 末尾8秒から冒頭8秒へ戻るLoopを確認する。 | BGM運用時の不連続を防ぐ。 |

### 001で今回確認する項目

- [ ] 0:00からBassが存在し、無音になっていない。
- [ ] 0:00〜2.00秒に、Piano、Drums、Melody、効果音が知覚されない。
- [ ] Bassのアタックにクリック、金属音、クラッチ音、機械音がない。
- [ ] 導入の左右差が小さく、中央に安定している。
- [ ] 今回変更したパラメータは一つだけである。

## 4. 002用編集シート

002は001と同一の導入を目標にせず、Bassから伴奏へ進む密度と空間の遷移を主軸にする。現行分析では、002のテンポ解釈に82.72 BPMと125.00 BPMの候補が残るため、Fender Studioのグリッドと実際の拍感を社長が確認し、採用したテンポをmanifestへ記録する。[2]

| 編集順 | Fender Studioでの操作 | 確認目的 |
|---|---|---|
| 1 | 002参照音源を別トラックに読み込み、波形と拍感を見ながら仮テンポを設定する。 | テンポ前提を固定する。 |
| 2 | 0〜8秒のBassと伴奏の音量オートメーションだけを作る。 | 密度遷移を単独で評価する。 |
| 3 | Piano導入のタイミングを一箇所だけ調整する。 | Bassから伴奏への交代を自然にする。 |
| 4 | Drumsと空間処理は最後に最小限で加える。 | 初期段階での要因混入を防ぐ。 |
| 5 | Loop、全体RMS、違和感の有無を聴取し、書き出す。 | BGMとしての実用性を確定する。 |

## 5. 書き出しと引き渡し

1. 書き出す前に、今回の変更変数を一文で記録する。
2. `WAV 48 kHz / 24-bit / Stereo`を正本として書き出す。Fender Studioの画面で利用可能な形式が異なる場合は、形式をmanifestに正確に記録する。
3. 必要ならMP3試聴版を併記するが、測定の正本はWAVとする。
4. manifestと任意の聴取メモを`05_notes/`へ置く。
5. 共有フォルダまたはGitHubに書き出しデータを渡す。公開制限がある音源は、GitHubへ直接置かず、安全な共有方法を別途選ぶ。

## 7. COOへの引き渡し後の流れ

Manus AIは、提出WAVを001・002の正本と同一条件で測定し、Fact／Hypothesisを分離した結果を返す。修正依頼は「最も影響の大きい一変数」だけに限定する。社長はFender Studioで反映し、次版を書き出す。この反復により、Suno候補の揺らぎを制作工程で吸収する。
