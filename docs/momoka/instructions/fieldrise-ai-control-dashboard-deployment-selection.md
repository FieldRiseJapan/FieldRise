# 桃花への正式指示書｜FieldRise AI Control Dashboard 公開先選定・公開実行

## 社長決定
現在完成している `dashboard/ai-control-dashboard/` を、社長が実際にアクセスできる公開Webアプリとして公開すること。

## 1. 公開先の選定
以下の優先順位で確認する。

第1候補：GitHub Pages。FieldRise GitHub環境との親和性、維持費、自動デプロイの容易さ、現在の静的Webアプリ構成との適合性を確認する。問題なく公開できる場合はGitHub Pagesを採用する。

第2候補：GitHub PagesがSPAルーティング、自動デプロイ、必要なAPIアクセス、セキュリティ、今後の保守等で不適合な場合はVercelを検討する。

その他の有料サービスを勝手に契約・導入しないこと。

## 2. 公開実行
公開先を決定したら、本番ビルド、デプロイ設定、自動デプロイ設定、公開、公開URL取得まで実施する。

## 3. 公開後の実ブラウザ検証
PCとスマートフォンの両方で、初期表示、ダークUI、Blue表示、検証バロメーター、001/002、G01〜G09、桃花通信、最新報告、同期状態、最新コミットを確認する。スマホでは横スクロール、可読性、操作性、情報欠落も確認する。

## 4. GitHub自動更新テスト【最重要】
安全なテストデータを使用し、GitHub更新→自動検知→60秒以内→ダッシュボード反映を実際に確認する。本番正本を壊さない方法で実施する。

## 5. E2Eテスト
公開URLを対象にE2Eテストを実施。失敗した場合は原因特定→修正→再デプロイ→再テストを行う。

## 6. 完成条件
以下すべてを満たした場合のみ完成とする。
- 公開URLあり
- PC正常
- スマホ正常
- GitHubデータ取得
- GitHub自動更新
- 60秒以内の反映確認
- E2E成功
- 重大エラーなし

## 7. 報告
完成後、`docs/momoka/reports/latest_report.md` に正式報告する。報告内容：公開先、公開URL、公開方法、自動デプロイ方法、GitHub自動更新方法、PC検証結果、スマホ検証結果、E2E結果、残課題。

公開完了を確認するまで「完成」と報告しないこと。

**社長決定：この指示書を正式な公開・検証指示として扱う。**
