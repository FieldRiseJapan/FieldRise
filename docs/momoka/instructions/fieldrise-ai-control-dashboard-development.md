# 桃花への正式開発指示書｜FieldRise AI Control Dashboard Web App

## 社長決定
本指示書を正式な開発指示として扱い、実運用可能なWebアプリとして完成させること。

## 目的
社長がFieldRiseの現在状況を一目で把握できるWebアプリ型AI管制ダッシュボードを構築する。

## デザイン
- 完全ダークUI
- Blueをメインカラー
- シンプルだが高級感・先進感のあるAI管制室デザイン
- 基本的に画像は使用しない
- 情報を主役にして装飾過多にしない
- PC・スマートフォン双方に対応

## メイン表示
### 総合検証スコア
0〜100のバロメーター形式で表示する。例：再現度 82/100。
ゲージだけでなく、この数字が何を意味するのか短い説明を付ける。

### 項目別検証
GitHubに存在する正式データを基準に、Bass、Piano、Intro、BPM、Structure、不要ノイズ、ループ感などを表示できる設計にする。ただし正式データが存在しない項目を勝手に作らない。

### 検証ステージ
001、002、A1、B1等を現在の正式データに基づいて表示し、それぞれの意味を説明する。推測で定義しない。

## 桃花からの報告
正式報告先を確認し、最新報告をダッシュボードに表示する。少なくとも以下を確認対象とする。
- `cto/inbox/momoka-comments.md`
- `docs/momoka/reports/latest_report.md`

表示項目：日時、報告種別、関連タスク、内容、ステータス、次のアクション。

## GitHub連携【最重要】
GitHubを唯一の正本（Source of Truth）とする。

GitHubにデータが追加・変更された場合、GitHub→自動検知→ダッシュボード更新となる仕組みを構築する。可能ならWebhook / GitHub Actions等を使用し、アプリ側にも定期同期を設けて取りこぼしを防ぐ。

画面には以下を表示する。
- ONLINE / OFFLINE
- 最終同期時刻
- 最新コミット
- 同期エラー

## データ安全
- 推測値を表示しない
- データがない場合は「未登録」等で明示
- GitHub取得失敗時は明確なエラー表示
- 古いデータを最新データとして表示しない
- ダッシュボードからGitHub正本データを勝手に変更しない

## 技術
既存FieldRise環境との整合性を確認して最適な構成を選択すること。必要に応じてNext.js、GitHub API、GitHub Actions、Vercel等を利用してよいが、技術選定は運用コスト・保守性・既存環境との整合性を優先する。

## 開発手順
1. GitHubの既存構造・正式データ・最新ルールを確認
2. UI/UX設計
3. Webアプリ実装
4. GitHub連携
5. 自動更新実装
6. 実データで動作確認
7. PC・スマホ確認
8. エラー・データ欠損確認
9. E2Eテスト
10. 失敗があれば修正して再テスト
11. 実運用可能な状態を確認

## 完成条件
以下すべてを確認するまで完成扱いにしない。

GitHubデータ取得 → Webアプリ表示 → GitHub更新 → 自動反映 → 最新データ表示 → PC/スマホ正常 → E2Eテスト成功

「モック完成」ではなく、実際に運用できるWebアプリを完成させること。

## 完成報告

- アプリURL
- 完成状況
- 技術構成
- GitHub連携方法
- 自動更新方法
- テスト結果
- 問題点
- 今後の改善案
