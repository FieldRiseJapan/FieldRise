# 桃花への正式指示書｜自動伝達・受領・Claim・報告 E2E運用テスト

## 社長決定
正式運用が固定されたため、実際の通信経路をE2Eで検証する。目的は「GitHubに指示書を置いた」だけでなく、桃花が自動検出し、受領・Claim・実行・報告まで到達することを確認すること。

## 固定経路
- 正式指示書：`docs/momoka/instructions/`
- 正式報告書：`docs/momoka/reports/latest_report.md`
- タスク単位：GitHub Issue
- 伝達完了判定：桃花の受領・Claimを確認

## テスト名
`桃花｜運用通信テスト｜自動伝達・受領・Claim・報告確認`

## テスト手順
1. 本指示書を正式指示書として検出する。
2. 対応するGitHub Issueを検出する。
3. 桃花が自動受領したことを記録する。
4. Claimを行い、実行名を上記テスト名にする。
5. `in_progress` へ遷移する。
6. 実作業として、固定運用の各経路が正しいことを検証する。
7. `docs/momoka/reports/latest_report.md` に結果を正式報告する。
8. `completed` へ遷移する。

## 禁止事項
指示書パス、報告書パス、Issueによる通信経路、Claim方式を勝手に変更しない。変更が必要な場合は、変更前に社長へ理由と変更案を注意・報告し、社長の「決定」後のみ変更する。

## 失敗判定
Issue作成後に自動受領・Claimが確認できない場合、「自動伝達未確認」として報告する。GitHubにファイルが存在することだけをもって伝達完了としない。

## 完了条件
自動検出 → 受領 → Claim → 正式実行名 → in_progress → 正式報告 → completed の全工程を確認すること。
