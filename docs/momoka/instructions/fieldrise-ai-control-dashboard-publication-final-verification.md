# 桃花への正式指示書｜FieldRise AI Control Dashboard 公開・最終検証

## 社長決定
現在実装済みの `dashboard/ai-control-dashboard/` を、社長が実際にアクセスできる公開Webアプリとして完成させること。

## 1. 公開環境
既存FieldRise環境との整合性を確認し、適切な公開先を選定する。候補はGitHub Pages、Vercel、その他既存環境と整合する静的ホスティング。勝手に有料サービスへ変更・契約しないこと。公開URLを確定し正式報告する。

## 2. 公開前チェック
- `pnpm build` 成功
- TypeScriptエラーなし
- GitHubデータ取得
- GitHub最新コミット取得
- 桃花最新報告取得
- 検証データ表示
- 001/002表示
- G01〜G09表示
- 同期状態表示
- 最終同期時刻表示
- エラー表示
- 手動再同期
- 60秒自動更新

## 3. 実ブラウザ検証
公開URLを実際のブラウザで開き、PCとスマートフォンの両方で初期表示、GitHub同期、各カード、検証バロメーター、桃花報告、次アクションを確認する。スマホでは横スクロール、可読性、操作性、情報欠落も確認する。

## 4. GitHub自動更新テスト【最重要】
安全なテスト用データ変更を使い、GitHub変更→60秒以内の自動再取得→ダッシュボード反映を実際に確認する。本番の正本データを壊さない方法で実施する。

## 5. 検証点数
GitHub正本に総合再現度の正式数値が存在しない場合は勝手に点数を作らず「未登録」と表示する。正式な総合点・履歴データが追加された場合のみ自動表示できる設計を維持する。

## 6. 完成条件
以下すべてを満たした場合のみ完成とする。
- 実装済み
- 公開URLあり
- 実ブラウザ確認済み
- スマホ確認済み
- GitHub自動更新確認済み
- E2Eテスト成功
- 重大なエラーなし

## 7. 完成報告
正式報告先へ以下を報告する。
- 公開URL
- 公開環境
- 自動更新方式
- 現在の検証データ
- テスト結果
- スマホ確認結果
- 残課題
- 公開上の注意点

「実装完了」と「公開完了」を混同しないこと。モックやローカル実装だけで完成報告しないこと。

**社長決定：この指示書を正式な開発・公開・最終検証指示として扱う。**
