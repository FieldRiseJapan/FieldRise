# 桃花への正式修正指示書｜実行画面「桃花受領：未指定」の根本修正

## 社長決定
Issue #10で決定した実行名自動命名ルールが実際の桃花の実行処理・実行画面に反映されていない。現在 `桃花受領：未指定` と表示されているため、実行開始処理そのものを修正し、必ず正式な `execution_name` を設定する。

## 1. 最重要要件
桃花が正式指示をClaimして実行を開始する時点で、必ず `execution_name` を生成してから実行を開始すること。GitHubへ後から名前を書くだけでは不十分。実行ランナー／実行タスク画面へ実行名を渡すこと。

## 2. 正式な実行名
原則：`桃花｜#Issue番号｜プロジェクト名｜作業内容`
今回：`桃花｜#12｜AI Control Dashboard｜公開後検証・最終確認`
Issue番号が取得できない場合：`桃花｜プロジェクト名｜作業内容`

## 3. 実行名生成フロー
GitHub Issue検出 → 正式指示書取得 → Issue番号取得 → プロジェクト名取得 → 作業内容取得 → execution_name生成 → Claim → 実行開始 → 実行画面へexecution_name表示 → GitHubへ記録 → ダッシュボードへ表示。

**execution_name生成前に実行を開始しないこと。**

## 4. 「未指定」の扱い
`桃花受領：未指定`、`未指定`、`Task`、`Untitled`、`Unknown` を禁止する。名前生成に必要な情報を取得できない場合は実行を開始せず、「実行名生成失敗」としてエラー報告する。

## 5. 既存タスク
現在すでに `桃花受領：未指定` で実行中のタスクを確認する。可能なら正式な実行名へ更新する。更新できない場合は、変更できない理由、実行名が固定されている箇所、今後改善するための修正箇所を調査・報告する。

## 6. ダッシュボードとの統一
以下の3箇所で同じ `execution_name` を使用する。
1. 桃花の実行画面
2. GitHub Claim / 作業記録
3. FieldRise AI Control Dashboard

それぞれ別の名前を生成しない。`execution_name` を唯一の正式名称とする。

## 7. テスト
- Issue #12をテスト対象とし、実行開始時点から `桃花｜#12｜AI Control Dashboard｜公開後検証・最終確認` が表示されること
- GitHub Claimにも同じ名前が記録されること
- ダッシュボードにも同じ名前が表示されること
- 新しいIssueでも自動命名されること
- 情報取得失敗時に「未指定」で実行せずエラーになること

## 8. 完成条件
Issue検出 → execution_name自動生成 → Claim → 実行画面表示 → GitHub記録 → ダッシュボード表示が一貫して動作し、新規タスクで `桃花受領：未指定` が発生しないこと。

## 9. 完了報告
`docs/momoka/reports/latest_report.md` に原因、修正箇所、execution_name生成方法、実行画面への反映方法、GitHub連携、ダッシュボード連携、既存タスクへの対応、テスト結果、残課題を報告する。

**「ルールを追加した」だけでは完了扱いにしない。実際の桃花実行画面で名前が表示されることを確認すること。**

**社長決定：この指示書を正式な桃花実行システム修正指示として扱う。**
