# 桃花への正式指示書｜タスク実行名・自動命名ルール

## 社長決定
桃花がGitHubの正式指示を受領・Claimした際、実行中タスクの内容が一目で分かる実行名を自動生成する。`桃花受領：未指定` のような曖昧な実行名は禁止する。

## 1. 基本命名規則
原則：`桃花｜#Issue番号｜プロジェクト名｜作業内容`

例：`桃花｜#9｜AI Control Dashboard｜公開先選定・公開実行`

## 2. Issue番号がない場合
`桃花｜プロジェクト名｜作業内容` とする。

## 3. 作業内容の取得優先順位
1. GitHub Issueタイトル
2. 正式指示書のタイトル
3. 指示書本文の目的・作業内容

`未指定` だけを実行名として使用しないこと。

## 4. Claim時の自動生成
正式指示を受領 → Issue・指示書を解析 → 実行名を自動生成 → Claimへ記録 → タスク実行、の順序にする。

## 5. Claimに記録する項目
可能な限り以下を記録する。
- `issue_number`
- `instruction_path`
- `project_name`
- `task_name`
- `execution_name`
- `status`
- `claimed_at`
- `report_path`

## 6. ダッシュボード連携
ダッシュボードでは実行中タスクを `実行名｜ステータス｜開始日時｜Issue` として表示できるようにする。

## 7. 既存タスク
現在実行中のタスクについても、既存のIssue・正式指示書から実行名を再構成できる場合は再構成し、`未指定` を解消する。

## 8. 禁止事項
以下のような作業内容を判断できない名称を使用しない。
- `桃花受領：未指定`
- `Task`
- `Untitled`
- `Unknown`
- 内容が分からない番号だけの名前

## 9. 完了条件
今後、桃花が正式指示をClaimした際、必ず人間が見て何を実行しているか分かる実行名が付いていること。ダッシュボードにも同じ実行名を表示できる状態にする。

**社長決定：このルールを正式な桃花運用ルールとして扱う。**
