# 桃花COO向け正式指示｜Project-001 001再現検証

**発行:** 彩花 CTO
**発行日:** 2026-08-15
**対象:** Project-001｜Cafe 001 完全再現検証
**最終目的:** 001・002再現精度向上 → Cafeシリーズ継続投稿
**指示正本:** `docs/momoka/instructions/`
**正式報告先:** `docs/momoka/reports/latest_report.md`

## 1. 目的

成功モデル001をMasterとして固定し、001の音響的特徴をFactとして測定・整理し、再現可能な生成条件を確立する。目的は新曲を感覚的に作ることではなく、001・002再現に有効な条件を検証し、その知識をCafeシリーズの継続制作へ再利用すること。

## 2. 検証原則

- 001を基準音源として固定する。
- 002は比較対象として扱う。
- Fact / Hypothesisを明確に分離する。
- 1回の検証で変更する主要変数は原則1つ。
- 「良い／好き」ではなく、基準との差分を記録する。
- 推測値をFactとして登録しない。
- 実測結果、聴感評価、仮説を別々に扱う。

## 3. 検証順序

### Phase 1｜冒頭0〜2秒

最優先で以下を確認する。

- Bassの実在
- Bass開始時刻
- 0〜2秒の音量推移
- Bassのアタックと質感
- Piano / Drumsの侵入時刻
- クラッチ音、クリック、金属的ノイズ等の有無

### Phase 2｜Bass

- 音色
- 音域
- 発音方法
- アタック
- サステイン
- 001との差分

### Phase 3｜Piano

- 音数
- フレーズ長
- 休符
- メロディー密度
- 動画投稿者の声を邪魔しない配置

### Phase 4｜Drums / 空間 / Dynamics

- ドラム特性
- リバーブ
- ステレオ幅
- 音量変化
- 全体密度

### Phase 5｜全体再現

個別検証の結果を統合し、再現用Prompt・設定・Negative指定へ昇格させる。

## 4. 桃花の作業

1. `main` ブランチ上の最新の001・002関連正本を確認する。
2. 既存A1/B1等の分析と矛盾がないか確認する。
3. Fact / Hypothesis / Evidence / Resultを整理する。
4. 実測可能な項目は時刻・区間・比較結果を記録する。
5. 詳細資料を適切なフォルダへ保存する。
6. 詳細資料は必ず正式報告 `docs/momoka/reports/latest_report.md` から辿れるようにする。
7. **未完了・停止・ブロッカーでも必ず最新報告を更新する。** 完了した時だけ報告する運用は禁止。
8. 作業完了時は、完全なCommit SHAとPush先を報告する。
9. GitHubファイル更新時、mainが進んでいる可能性を考慮し、対象ファイルの**最新SHAを再取得してから更新**する。409 Conflictが出た場合は古いSHAで再試行せず、最新SHAを取得してから更新する。

## 5. Prompt設計ルール

彩花が次の検証Promptを設計する際は必ずセットで出す。

1. 生成プロンプト
2. SUNO AI設定
3. ネガティブ指定

検証目的から逸脱した大幅なPrompt変更は禁止する。

## 6. 現在特に重要な既知データ

過去検証では「0:00からBass」と明示しても、実生成では冒頭2秒にBassが存在しなかった。これは重要なFactとして扱い、単なるPrompt文言の強化だけで解決したと仮定しない。

## 7. 正式報告フォーマット

`docs/momoka/reports/latest_report.md` に最低限、以下を記載する。

1. 完了状況
2. 作成・更新ファイル
3. 完全なCommit SHA
4. Push先
5. 未完了・ブロッカー
6. 彩花CTOが次に確認するファイル
