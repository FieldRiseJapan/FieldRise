# 桃花向け正式指示書

このディレクトリは、社長の**「決定」後**に発行される、桃花（COO）への正式指示書の唯一の正本です。正式指示は、このディレクトリ直下に新規のMarkdownファイルとして登録し、`main` ブランチへPushされた時点で自動受領の対象になります。

> **運用原則:** Issueは通信・進捗管理、`docs/momoka/instructions/` は「何を実施するか」の正本、`docs/momoka/reports/latest_report.md` は「受領・進捗・完了・停止・ブロッカー」の正本、`cto/inbox/momoka-comments.md` は単独コメント・相談の正本です。指示・正式報告・単独コメントを混在させません。

## 指示書の必須項目

各正式指示書には、少なくとも次の項目を記載します。

| 項目 | 内容 |
|---|---|
| 決定状態 | 社長が「決定」したことを明示します。 |
| 指示ID | 重複しないIDを付与します。 |
| 関連Issue | 通信・進捗管理に使用するGitHub Issueを記載します。 |
| 正式報告先 | 原則として `docs/momoka/reports/latest_report.md` を記載します。 |
| 目的・範囲・制約 | 実施すべき内容と実施しない範囲を明記します。 |
| 完了条件 | 検証可能な完了条件を記載します。 |

## 自動受領フロー

| 順序 | 実施内容 | 証跡 |
|---:|---|---|
| 1 | 社長が「決定」する。 | 指示書の決定状態 |
| 2 | 正式指示書を本ディレクトリへ新規保存し、`main` へPushする。 | Gitコミット・Push |
| 3 | 自動処理が新規指示書を検知し、桃花へ受領要求を送る。 | `automation/momoka-receipts/` |
| 4 | 桃花が内容を確認し、Claimを登録する。 | `automation/momoka-claims/` |
| 5 | 桃花が作業を行い、受領・進捗・完了・停止・ブロッカーを正式報告先へ記録する。 | `docs/momoka/reports/latest_report.md` |
| 6 | 自動処理がClaimと正式報告を照合して受領を確定する。 | `automation/momoka-receipts/` |

過去の `cto/outbox/` および `music_ai/inbox/cto_to_coo/` の文書は履歴・案件固有の参考資料です。新規の桃花向け正式指示は本ディレクトリからのみ発行します。

## 命名規則

ファイル名は `YYYY-MM-DD_<指示IDの短縮名>.md` を推奨します。返信・参考資料・READMEは自動受領の対象外です。
