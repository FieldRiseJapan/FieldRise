# 桃花への正式指示書｜FieldRise AI Control Dashboard Web App

## 決定事項
社長決定。新しいダッシュボードを、単なるページではなく実際に運用できるWebアプリとして構築する。

## 目的
GitHubを唯一の正本（Single Source of Truth）として、社長が開くだけでFieldRiseのAI・音楽R&Dの現在状況を把握できる管制画面を作る。

## デザイン
- 完全ダークUI
- Blueをメインカラー
- 黒〜ダークネイビー背景、Blueアクセント、白〜ライトグレー文字
- シンプルだがカッコいい。過度な装飾は不要
- 画像・装飾画像は基本使用しない
- PC中心＋スマホ対応
- FieldRiseのAI管制室らしい洗練されたUI

## トップ画面
- FieldRise AI Control Dashboard
- システム状態
- GitHub同期状態
- 最終更新日時
- 最新GitHubコミット
- 現在の重要タスク

## 検証点数
検証点数は「再現度バロメーター」として視覚的に表示する。
例：82 / 100 ＋ ゲージ。

総合点だけでなく、可能な範囲でBass、Piano、Intro、BPM、構成、不要ノイズ、ループ感等の項目別スコアも表示する。
前回→今回→差分（±）も表示する。

## 数字の説明
数字だけを表示せず、短い説明を必ず付ける。
- 001＝基準曲001
- 002＝基準曲002
- A1＝第1回検証
- B1＝次回検証
- G01〜G09＝再現度評価項目
既存GitHubデータを確認し、実際の正式な意味と一致させること。推測で定義しない。

## 桃花の報告
正式な報告先・通信ルールを確認し、GitHubから最新報告を取得して表示する。
特に `cto/inbox/momoka-comments.md` を確認対象に含める。
表示項目：日時、種別、関連タスク、コメント、ステータス、次アクション。

## GitHub連携【最重要】
GitHubを正本とする。
GitHubにデータが追加・変更されたら、Webアプリへ自動反映する。
可能ならWebhook/GitHub Actions等を使用し、アプリ側の定期更新も併用して同期失敗時の取りこぼしを防ぐ。
最終同期時刻と同期状態を常時表示する。

## エラー対策
- GitHub取得失敗：明確なエラー表示
- データが古い：最終同期時刻を表示
- データ欠損：データ未登録と表示
- 推測値は表示しない
- Webアプリ障害がGitHub正本データを壊さない

## 既存システムとの関係
現在のSonata Desk等の既存資産・正式指示を確認してから設計すること。既存システムを勝手に削除・置換しない。
今回のWebアプリがSonata Deskを置き換えるのか、社長向け管制画面として併存するのかを既存ルールとGitHub正本から判断し、矛盾があれば着手前に報告する。

## 開発
1. GitHubの既存構造と最新データを確認
2. UI/UX設計
3. Webアプリ実装
4. GitHub連携
5. 自動更新実装
6. 実データで動作確認
7. PC・スマホ表示確認
8. エラー処理確認
9. 必要な修正
10. 完成報告

モックだけで終了せず、実際に運用できる状態まで完成させること。

## 完成条件
社長が開くだけで、以下が数秒で分かること。
- 001/002の現在の再現度
- 検証点数と前回との差
- 各数字の意味
- 桃花の最新報告
- 現在の問題
- 次のアクション
- GitHubの最新同期状態

基本フロー：
**GitHubにデータが入る → 自動検知・同期 → Webアプリ更新 → 社長が最新状態を確認**

## 報告
完成後、GitHubの指定された正式報告先へ以下を報告すること。
- 完成状況
- アクセス先
- 実装内容
- 自動更新の仕組み
- 動作確認結果
- 残課題（あれば）

**社長決定：この指示書を正式な開発指示として扱う。**
