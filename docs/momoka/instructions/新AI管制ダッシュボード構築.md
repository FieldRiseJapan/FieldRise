# 桃花への指示書：新AI管制ダッシュボード構築

## ステータス
- 承認状態：社長決定済み
- 正式送信先：GitHub Issue #5
- 指示書の正本：このファイル

## 目的
現在のダッシュボードを無理に修正せず、新しいダッシュボードを構築する。
GitHubを唯一の正本（Single Source of Truth）とし、GitHubのデータ更新を自動的にダッシュボードへ反映する。

## デザイン
- 完全ダークUI
- Blueをメインカラー
- 黒〜ダークネイビー背景＋Blueアクセント
- 白〜ライトグレー文字
- シンプルで情報過多にしない
- 画像・装飾画像は基本不要
- PC中心、スマホでも確認可能

## 最上段
「FieldRise AI Control Dashboard」として以下を表示：
- システム状態
- 最終更新日時
- 最新GitHubコミット
- GitHub同期状態

## 001/002再現状況
最重要エリアとして「再現度バロメーター」を表示。
例：82 / 100 ＋ 視覚的なゲージ。

項目別にBass、Piano、Intro、BPM、構成、不要ノイズ、ループ感等を表示し、前回→今回→差分も表示する。

検証番号は数字だけでなく意味を併記する。
- 001＝基準曲001
- 002＝基準曲002
- A1＝第1回検証
- B1＝A1を踏まえた次回検証
- G01〜G09＝再現度評価項目

## 桃花の最新報告
GitHubから自動取得し、最新報告、進捗、完了タスク、現在の問題、次の作業を表示。

## 自動更新【最重要】
GitHubへのデータ追加・変更を検知したら、自動的にダッシュボードを更新すること。
GitHub Actions等を利用し、可能ならmusic_ai/**の変更を重要な同期対象とする。

## エラー対策
- GitHub取得失敗：明確なエラー表示
- データが古い：「最終同期 ○分前」を表示
- データ欠損：「データ未登録」
- 推測値は表示しない
- ダッシュボード障害がGitHubデータへ影響しない設計

## 既存データ
既存GitHubデータを最大限活用し、既存データを壊さないこと。
特にmusic_ai/reference_music/、music_ai/experiments/、music_ai/suno_database/、music_ai/knowledge/、music_ai/reports/cafe/等を確認して利用すること。

## 開発方針
必要なスキル・技術を自律的に選択し、実装→動作確認→エラー修正→再確認まで行う。
モックではなく、実際にGitHubデータを読み込む動作するダッシュボードを完成させる。

## 完成条件
社長が開くだけで、桃花が何をしたか、001/002の再現度、前回との差、現在の問題、次の作業、最新データ更新時刻が数秒で分かること。

**GitHubにデータが入る → 自動検知 → ダッシュボード自動更新 → 社長が最新状態を確認**を基本設計とする。

完成後、動作確認結果とアクセス先を本Issueまたは指定の報告先へ報告する。
