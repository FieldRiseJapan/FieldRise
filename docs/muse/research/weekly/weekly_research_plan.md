# TikTok Jazz週次調査 運用計画

- **文書ID:** FR-MUSE-2026-11-002（運用計画編）
- **作成者:** Muse（FieldRise AI社員）
- **作成日:** 2026-11-03
- **根拠:** 正式業務指示書 FR-MUSE-2026-11-002 第2章（社長承認済み）
- **初回基準日:** 2026-11-09（月）

## 1. 実行方法（確認結果）

Museの実行環境には定期実行機能（スケジュール登録）があるため、GitHub Actions等の代替手段を使わず、以下のとおり正式にスケジュール設定した。

- スケジュール名：FieldRise TikTok Jazz週次調査
- 実行頻度：毎週月曜日
- 実行時刻：午前10時ごろ（日本時間。設定は柔軟時刻のため、実際の開始は数分前後する場合がある）
- 初回実行：2026-11-09（月）
- 実行者：Muse（このチャットに結果を報告する設定）
- 状態：設定済み・有効

各回の実行では、スケジュールに登録した指示文（調査範囲、記録ルール、保存先、報告形式）に従って自動で調査・保存・報告まで行う。

## 2. 調査範囲（各回共通）

- 対象期間：原則として直近7日間
- 対象地域：世界、米国、英国、日本（英語圏を最優先）
- 対象ジャンル：Piano Jazz、Smooth Jazz、Cafe Jazz、Lo-fi Jazz、Jazz Instrumental、Jazz-Pop
- 重視する用途：恋愛メッセージ、カフェ、朝のコーヒー、日常Vlog、写真スライドショー
- 情報源（無料のみ）：Metricool週次チャート、Virlo、Tokchart無料範囲、TikTok音源ページ、Spotify、Shazam、Chartexの無料公開範囲、接続済みツール（vidIQ、Spotify）の無料範囲
- 前週ファイルとの比較：同じ音源ID・同じ集計定義の累計値同士でのみ差分（増加数・増加率）を計算する

## 3. 費用

- 調査の実施費用：追加課金なし（無料情報源と接続済みツールの範囲のみ）
- 有料API・有料データ契約：使用しない。必要性が生じた場合は実施せず、社長へ事前提案として報告する
- GitHubへの保存：無料範囲（public リポジトリへの通常のコミット）

## 4. GitHub保存方法

- 週次調査ファイル：`docs/muse/research/weekly/<基準日YYYY-MM-DD>_tiktok_jazz_weekly.md`
  - 例：`docs/muse/research/weekly/2026-11-09_tiktok_jazz_weekly.md`
- 形式：週次調査テンプレート（`docs/muse/research/weekly/_template_tiktok_jazz_weekly.md`）を使用
- 最新報告：各回の要約を `docs/muse/reports/latest_report.md` に追記する（既存内容は削除しない）
- 保存後：ファイルを読み返して検証し、コミットSHAと保存先URLを社長へテキスト形式（コードブロック）で報告する
- 保存しない情報：認証情報、個人情報、非公開の収益詳細
- 変更しないもの：桃花COO専用ファイル（docs/momoka/ 配下）、自動化設定（本スケジュール自体の変更は社長の指示による）

## 5. 制約と注意点（正直な申告）

1. **週次チャートの上書き問題** — Metricool等の週次ページは上書き更新され、過去週の内容が残らない。本運用で毎週ファイル保存すること自体が、この制約への対策である。
2. **使用動画数の取得限界** — TikTok音源の使用動画数（累計）は、情報源によっては取得できない週がある。その場合は「未確認」と記録し、チャート順位の変化で代替しない。
3. **スケジュール実行の前提** — 定期実行はMuseの実行環境が稼働していることが前提である。実行できなかった週が発生した場合は、次回報告時にその旨と理由を明記する。
4. **初回（2026-11-09）の比較について** — 初回は前週ファイルが存在しないため、使用動画数の増加数・増加率は「未確認（初回のため比較対象なし）」とし、累計値の基準点（ベースライン）を記録する回とする。あわせて、MUSE-2026-11-001で記録した2026年10月時点の累計値（例：Self Aware 約750万本、Chopin Nocturne No. 2 Piano Mono 730万本。いずれも累計値）との参考比較は、集計定義が同一と確認できた場合のみ行う。
5. **GitHub Actions代替案について** — 本計画では定期実行機能が利用できたため不要となった。将来、実行環境を変更する場合は、無料枠のGitHub Actionsで「週次リマインドIssueの自動作成」までが代替可能な範囲であり、調査そのものの自動化はMuse側の実行が前提になる。

## 6. 運用の見直し

- 4回（約1か月）実施した時点で、取得できた項目と未確認が続く項目を整理し、運用計画の改定案を社長へ提案する。
- 有料データの必要性が継続的に生じる場合は、その時点で改めて社長へ事前提案する。
