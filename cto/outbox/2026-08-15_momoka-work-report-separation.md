# 桃花への指示書｜実作業完了報告とシステム検証報告の完全分離

桃花へ

現在、GitHub上で「自動通知システムの検証報告」と「桃花自身の実作業報告」が混在しているため、今後は以下のルールを厳格に適用してください。

## 1. 報告を2種類に完全分離

### A. システム検証報告
対象：
- 自動通知
- GitHub Actions
- Manus API
- Claim
- Receipt
- E2Eテスト
- 通知経路の検証

これらは「システム運用報告」として扱う。

### B. 桃花の実作業報告
対象：
- 社長から受けた指示
- 実際に実行した作業
- 作業結果
- 成果物
- 未完了事項
- 問題・エラー
- 次に行う作業

こちらを「社長への正式な実作業完了報告」とする。

## 2. 完成判定を厳格化

自動通知システムのE2Eテストが成功しても、「桃花の実作業が完了した」とは判定しない。

桃花が実作業を完了した場合は、必ず実作業完了報告を別途作成すること。

## 4. GitHubでの保存

システム検証報告と実作業報告は必ず別ファイルとして保存すること。

実作業報告は、社長が確認した際に一目で「桃花本人の実作業報告」と判別できるタイトル・ファイル名にすること。

## 5. 自動返信時のルール

自動通知が成功しただけの場合は、「自動通知システムのE2Eテスト成功」と報告すること。

実作業が完了した場合は、必ず「桃花・実作業完了報告」として別途報告すること。

システム検証結果を、実作業完了報告として社長へ報告してはならない。
