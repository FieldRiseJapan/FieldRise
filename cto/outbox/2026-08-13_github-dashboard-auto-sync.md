# 桃花への正式指示：GitHub→Sonata Desk 自動反映機構

宛先：桃花（COO / Project-001 AI秘書）
送信元：彩花（CTO）
日付：2026-08-13

## 承認

社長承認済みです。

**GitHubの更新を検知して、Sonata Desk（ダッシュボード）へ自動反映する仕組みの実装を開始してください。**

## 基本方針

GitHubを唯一の正本として維持します。

```text
GitHub（正本）
    ↓ 更新を検知
GitHub Actions等の自動処理
    ↓
表示用データを生成・更新
    ↓
Sonata Desk（ダッシュボード）へ自動反映
```

## 必須条件

1. GitHubへのデータ更新をトリガーとして自動反映する。
2. 手動でダッシュボードへデータを二重入力しない。
3. GitHub側の正本データを変更せず、表示用データは必要最小限に生成する。
4. 001・002比較、A1進捗、Pattern DB、検証台帳、参照音源の更新を反映対象とする。
5. GitHub Actions等、GitHub内で完結できる仕組みを優先する。
6. 外部DB・不要なSaaS・不要なAPI・AI処理を追加しない。
7. Credit消費を最小化する。
8. 既存Sonata Deskの構成を可能な限り再利用する。
9. 更新失敗時に原因を追跡できるログ・ステータスをGitHub上で確認可能にする。
10. 自動反映によってGitHubを唯一の正本とする原則を壊さない。

## 実装前に確認すること

- 現在のSonata Deskの構成
- GitHub上の正本データの場所
- 現在の公開・デプロイ方法
- GitHub Actions利用可否
- 自動反映に必要な最小ファイル構成

不要な大規模改修は行わないでください。

## 完了条件

以下を実際に確認してから完了報告してください。

- GitHub上の対象データを1件変更
- 自動処理が起動
- Sonata Deskへ反映
- 反映された内容が正本と一致
- 手動更新なしで反映できることを確認
- 失敗時に追跡可能であることを確認

## 報告内容

完了後、GitHubへ以下を報告してください。

- 実装ファイルのパス
- GitHub Actions等のワークフロー
- トリガー条件
- 対象データ
- デプロイ・反映方法
- 実際の自動反映テスト結果
- 反映までの所要時間
- 未実装項目
- 問題点・制約
- 今後の改善案

**「自動化した」と書くだけでは完了としません。実際にGitHubを変更してSonata Deskへ自動反映された証拠を確認してから完了報告してください。**
