## 実PDFによる最終通しテスト

入力は `20260824152536.pdf`（4ページの画像PDF）です。300dpiレンダリング、枠候補検出、セル単位OCR候補化、除外判定、電線コード別Excel作成を通し実行しました。4ページから24枠、369行候補を処理し、Excelパッケージの整合性テストに成功しました。処理時間は開発環境で約2分半でした。会社PCではPDFの大きさ・PC性能により変わるため、画面の推定残り時間は処理実績をもとに表示します。

初回テストでは接続先や端子番号を電線サイズとして誤認し、173シートを作成する不具合を検出しました。抽出対象を左右接続先にある「色＋サイズ」の形式に限定し、標準サイズの確認と、OCRでの0/O混同に対する色コード制限を加えて修正しました。

最終回帰テストでは、`概要`、`G2`、`Y2`、`Y3`、`Y5`、`未分類`の6シートを生成しました。OCRで十分に確信できない線コードや未登録サイズは、推測でサイズシートを増やさず`未分類`に残します。この設計により、誤ったサイズ別シートを作るよりも安全に利用者確認へ回せます。

## 持ち運び版の検証基準

GitHub ActionsのWindowsビルドでは、`yutakaeng.exe`、OCR実行ファイル、OCR辞書、起動説明書を同じフォルダへまとめます。成果物フォルダ全体をUSBメモリーへコピーして使用する構成であり、会社PCでの個別インストールを前提にしません。ビルド時にはルールテスト、実行ファイルの存在、OCR同梱フォルダの存在を確認します。

## 残る検証上の注意

この版は検証用です。OCR候補は自動確定せず、未分類・未確認・警告をExcelに残します。電線コードの候補はPDFごとに利用者が確認し、必要なサイズ表記をサイズマスターへ追加する前提です。最終ホットマーカー用データは、利用者による全行確認と警告0件の後にのみ確定します。

## ZTブロックのLEFT盤間配線の追加検証

利用者指摘を受け、ZTブロックの`LEFT-Y5`について、`RIGHT-Y5`と同じく対象外にしないことを明示テストしました。自動テストでは、`LEFT-Y5`から`Y5`を抽出し、ZT1のLEFT、RIGHT、LEFT/RIGHT併記のいずれも除外理由が空文字になることを確認しました。

実PDFのページ3にあるZT1(14)から、`LEFT-Y5`を含む行を再抽出しました。最終回帰Excelでは、`Y5`シートの11行目に`ZT1(14)`、左側接続先候補`LEFT-Y5`、読取状態`未確認`、確認状態`未確認`として出力され、対象外ではないことを確認しました。

> この確認は、LEFT盤間線を候補Excelとサイズ別シートに残す検証です。盤間の対応先端子を利用者が確認した後、同一電線として主文字を2個のホットマーカー候補へ数える最終照合は、全行確認段階で行います。


## 2026-08-26 主文字OCRのオフライン改善回帰

従来のTesseractによる中央セルOCRは、罫線・端子番号・隣接列の影響により`RTRP`などの無意味な主文字候補を生成することがありました。このため、主文字だけをローカルONNX方式のRapidOCR 3.9.2へ切り替えました。認識器には中央セルが既知であることを利用した認識専用モードを使い、検出器による誤った領域分割を使いません。

| 検証項目 | 結果 |
|---|---|
| TF-Bの21既知主文字 | 21/21一致 |
| 確認値の例 | `BTBP`、`BTBN`、`D31S14`、`D31S21`、`BTFP1`、`BTFC3` |
| 別種別の目視照合 | `BTSH2A`、`FL1A11-SF`、`RS485PY11`、`RS485PY1`で一致 |
| 4ページ実PDF `20260824152536.pdf` | 396行候補、約150秒で完走 |
| 4ページPDFの主文字警告 | 167件を空欄＋警告として残し、無意味候補を出力しない |
| 6ページ実PDF `20260824152320.pdf` | 947行候補、約373秒で完走 |
| 6ページPDFの主文字警告 | 422件を空欄＋警告として残し、概要とExcel明細の警告件数一致を確認 |
| ZT LEFT/RIGHT業務ルール | 自動テスト継続合格 |

主文字は同じセルを広い切出しと狭い切出しで2回認識します。完全一致、または狭い方が末尾だけ欠けたことを確認できる前方一致の場合だけを候補として採用します。候補が食い違う、信頼度が低い、許容英数字・記号以外を含む、数字だけである、または実証済みの`BTBP`・`BTBN`以外の英字のみ候補である場合は、主文字セルを空欄にして`主文字候補不一致`または`主文字未読取`を警告します。

> これにより、読めない主文字をもっともらしい文字列としてExcelへ書き出すことを禁止します。警告行は接続先も空欄であっても未分類シートに残し、概要の警告件数と明細の警告件数が一致することを確認しました。

## 2026-08-26 Windows持ち運び版の同梱方針

WindowsビルドではRapidOCR、ONNX Runtime、RapidOCRモデルを実行フォルダ内の`_internal`へ同梱します。主文字に使う認識モデル`PP-OCRv6_rec_small.onnx`は約21MBです。アプリ起動後にモデルをダウンロードしないため、USBでフォルダ全体をコピーしたネット未接続の会社PCでも、PDF・図面データを外部送信せずに主文字OCRを実行できます。

## 2026-08-27 写真準拠のExcel出力変更

利用者提供のExcel写真を基準に、マーク主文字を「盤番号-見出しまたは端子台-主文字」の順に出力する仕様へ変更した。例として盤番号1AのYF枠で主文字がFL1A11の場合は`1A-YF-FL1A11`、盤番号3AのT1(2)で主文字がBTBT2BPの場合は`3A-T1-BTBT2BP`となる。端子台の括弧内面番号は、先頭識別子としてはT1に統一する。盤番号または見出しが読めない場合は推測で補わず、警告として残す。

電線サイズ別シートは、図面から実際に抽出できたサイズのグループだけを作成する。電線サイズを特定できない行、見出しを分類できない行、行き先を読み取れない行はサイズ別シートへ混ぜず、`警告一覧`へ集約する。これは誤ったサイズシートや誤ったマークデータを増やさないための安全措置である。

確認状態は全行を人手で確認する運用から変更し、正常に読み取れた行は`確認不要`、読み取れない項目や行き先不明を含む行だけを`警告確認`とする。警告理由には主文字・L側・R側など、どの項目が未読取または不確かかを記録する。利用者は警告行だけをExcel上で修正でき、主文字欄は通常のExcelセルとして編集可能である。

自動回帰では、`compose_mark_text("3A", "T1(2)", "BTBT2BP")` が`3A-T1-BTBT2BP`を返すこと、Y2シートの先頭列が写真の指定順を維持すること、正常行が`読取済み・確認不要`、未読取行が`警告あり・警告確認`となることを確認した。`tests_pipeline_rules.py` と `tests_excel_layout.py` は全項目合格した。

## 2026-08-26 全画面処理ログ・実時間ETA・Copilot警告セル補助

解析開始直後に `progress(0, 総ページ数)` を通知するよう変更した。これにより、最初のページ処理が終わるまで総ページ数が不明で、推定残り時間を表示できなかった問題を解消した。PySide6側のタイマーは250ミリ秒ごとに更新し、ページ処理時間の実測値を平滑化して推定値を更新する。処理中はPDFドロップ画面と選択ボタンを一時的に隠し、コード風のライブログが画面の大部分を占める表示へ切り替える。

4ページ実PDF `20260824152536.pdf` で初期進捗 `0/4`、途中 `1/4`、完了 `4/4` を確認した。処理時間は91.9秒、候補行は230行、警告行は79件だった。警告セル画像はデスクトップ上の専用確認フォルダへ79件だけ保存された。正常行やPDF全体は外部支援用フォルダへ保存していない。Python構文検査、`tests_pipeline_rules.py`、`tests_excel_layout.py` は全項目合格した。

解析完了後、警告画像が存在する場合だけ「Copilotへ警告セルを確認依頼」ボタンを表示する。利用者は警告画像を1件だけ選択し、画像を確認したうえでCopilotのページを開く。画像のCopilot添付は利用者が手動で行い、アプリからPDF全体や複数行を自動送信しない。Copilotの回答は候補として扱い、原図照合なしにExcelへ確定反映しない。外部送信を希望しない場合はボタンを使わず、完全オフライン運用を継続できる。
